Android API coverage (Apêndice C)

Fonte: RustyDroid.md Appendix C. Janela: API 26–36. Superfícies registradas: 106 em 17 domínios (supported 4, partial 102, stub 0, not_implemented 0).

Semântica honesta: supported significa modelo host com estado para o subconjunto documentado em notes/key_apis, não o pacote AOSP inteiro. partial executa um subconjunto real; stub é hierarquia/fallback; not_implemented não tem modelo host. Presença em DEX ou numa hierarquia stub não é cobertura de execução — para execução use MCP get_coverage.

Como atualizar

  1. Ao mudar uma API Android, atualize a linha correspondente em data/api-coverage.toml no mesmo PR.
  2. Rode rd api-coverage check --json (ou os testes de rd-framework).
  3. Regenere este arquivo e a tabela da spec com cargo xtask api-coverage-report e cargo xtask api-coverage-spec.
