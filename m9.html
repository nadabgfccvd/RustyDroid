RustyDroid Documentation

M9 — Advanced components and NDK

Status: ✅ implemented; human review approved (2026-10-21). The user reviewed and approved the full M9 deliverable in this session. Every M9 capability below is implemented and covered by tests. In all five real F-Droid APKs, the DEX code calls a JNI method and the native code returns a result that is checked independently. The same check passes for each APK’s x86_64, arm64-v8a and armeabi-v7a libraries (15/15 runs). See Gate evidence and Known limits for exactly what was and was not verified.

Design decision record: ADR 004.

Architecture

 DEX (rd-vm interpreter)
   │  native method / System.loadLibrary
   ▼
 rd-vm::native  ── JNI function table (JNIEnv*, JavaVM*), local/global refs (rd-jni)
   │  typed calls, no raw pointers into the VM heap
   ▼
 rd-ndk::runtime ── ELF loader (rd-ndk::elf), relocation, imports, libc shim,
   │                arena allocator, watchdog / fuel accounting
   │  line-delimited JSON over stdin/stdout
   ▼
 native_worker.py ── Unicorn 2.1.4 CPU emulator in a separate process
                     (x86_64, AArch64, ARM/Thumb); syscalls/SVC blocked
  • No host dlopen and no new unsafe. Guest code never runs on the host CPU. The Rust side only parses bytes and exchanges IPC messages.
  • GPL isolation. Unicorn is GPL-2.0. It runs in a separate interpreter process launched at runtime. It is never linked into the MIT/Apache binary.
  • Determinism and limits. Every call has an instruction budget (fuel) and a wall-clock watchdog, plus memory and arena caps. Fuel is the deterministic limit: instruction counts are identical across machines, including GitHub runners. The per-call wall-clock net defaults to 30 s (RD_NATIVE_CALL_SECS, 1–120). An earlier 5 s net made armv7 binaryeye flaky under load. JNI arrays and strings are capped at 1,000,000 elements. A failure surfaces as a typed VmExit/Error, never a host crash.
  • Fail-closed libc. Libc imports that are not implemented return a typed NOT_IMPLEMENTED that names the symbol. The fd layer exposes only stdio. Any other descriptor returns EBADF. Lock and condition-variable signalling calls are uncontended successes because the guest is single-threaded. pthread_cond_wait would block forever, so it stays unimplemented.

Installing the native worker

pip install unicorn==2.1.4          # or into a private prefix
export RD_NATIVE_PYTHON=python3     # interpreter that can `import unicorn`
cargo build -p rd-cli --features native

RD_NATIVE_PYTHON defaults to python3. The worker script is embedded in the binary (include_str!) and passed to the interpreter with -c, so nothing is written to disk.

ABI fixtures for the tests are built from golden/native/fixture.c with bash golden/native/build.sh. This needs gcc, gcc-aarch64-linux-gnu and gcc-arm-linux-gnueabihf. The artifacts are gitignored.

Supported surface

SYS-09 — notifications, IME, widgets

  • Notifications. Covers channels and groups, NotificationChannel getters/setters (importance cannot change after registration), and Notification.Builder and NotificationCompat.Builder. The builder supports title, text, subtext, channel, group/summary, category, small icon, ongoing, auto-cancel, only-alert-once, visibility, priority, number, progress, content and delete intents, setTimeoutAfter, actions and BigTextStyle. Also covered: notify/cancel/cancelAll and the targetSdk 33+ POST_NOTIFICATIONS permission gate (denied by default for targetSdk ≥ 33; agents grant it explicitly). PendingIntent (getActivity/getBroadcast/getService/getForegroundService) is dispatched into the DEX. On targetSdk ≥ 31 it requires a mutability flag, as on Android. Clicking a notification fires its intent and applies auto-cancel. Timeouts expire notifications, and NotificationListenerService posted/removed callbacks are delivered.
  • IME. Covers focus and keyboard visibility on EditText, InputConnection (commitText, setComposingText, finishComposingText, deleteSurroundingText, setSelection, performEditorAction), and the InputMethodService lifecycle (onCreate, onStartInput, onFinishInput). Text and selection handling are Unicode-correct.
  • Widgets (RemoteViews). Covers AppWidgetManager/AppWidgetHost allocate, bind and delete, and the AppWidgetProvider DEX lifecycle (onEnabled, onUpdate, onDeleted, onDisabled). RemoteViews supports setTextViewText, setViewVisibility, setOnClickPendingIntent and setBoolean(id, "setEnabled", …). Other RemoteViews setters are not intercepted; other setBoolean targets fail with NOT_IMPLEMENTED. Widgets render into the same UiNode tree as activities, and widget_screenshot captures them. Clicking a widget dispatches its PendingIntent.

SYS-10 — accessibility and shortcuts

  • Accessibility. Builds a node tree from the live view hierarchy, including content descriptions. AccessibilityEvent objects are delivered to registered AccessibilityService DEX callbacks. Supported actions are focus, click and set text, and set text goes through the same editor model as the IME.
  • Shortcuts. Covers ShortcutManager: set/add/update/remove/ removeAll dynamic shortcuts, enable/disable, requestPinShortcut, getDynamicShortcuts/getPinnedShortcuts, ShortcutInfo.Builder (labels, intent, rank) and launch through intent dispatch. ShortcutManagerCompat is not intercepted; it falls through to the APK’s androidx DEX.

LANG-02 — NDK

  • ELF loading and relocation for x86_64, AArch64 and ARM (EABI5, hard-float).
  • JNI_OnLoad, static symbol lookup by mangled name, and RegisterNatives.
  • Primitive, wide and float/double arguments and returns. Up to 8 integer-class arguments have been tested, plus stack spill.
  • Strings (modified UTF-8), primitive arrays (get/release/region), callbacks into Java, and exceptions in both directions. A native Throw becomes a VM exception.
  • Repeated loadLibrary calls do not re-run constructors.

Known limits

These are deliberately unsupported and fail typed rather than silently:

  • No threads. pthread_create and pthread_cond_wait are not implemented. de.jurihock.voicesmith’s libvoicesmith is driven through JNA (libjnidispatch, see below), not JNI, so it is not part of the gate.
  • Nested native reentrancy is refused. This means native code calling Java that then calls another native method.
  • Syscalls and SVC are blocked in the worker. The fd layer only exposes stdio, and everything else returns EBADF.
  • Large arrays. JNI arrays are capped at 1,000,000 elements. termux-bootstrap’s roughly 30 MB getZip array exceeds that.
  • JNA libjnidispatch. JNI_OnLoad returns 0 because its java.lang reflection lookups are not implemented.
  • RemoteViews ProgressBar, image/colour setters and collection widgets (RemoteViewsService) are not implemented.
  • No real text shaping in widget screenshots. They use the M4 bitmap font.
  • Components were verified on fixture APKs. Notifications, IME, widgets, accessibility and shortcuts were tested with rd-testsupport’s test.m9 fixture and the agent tools, not with a third-party app.
  • TFLite inference. Model loading needs direct ByteBuffers (NewDirectByteBuffer/GetDirectBufferAddress), which are not implemented.
  • Performance. Emulation through Unicorn plus IPC is orders of magnitude slower than native code. That is acceptable for testing and agent work, not for running heavy native workloads.

Gate evidence

Fixture tests (all three ABIs):

  • cargo test -p rd-ndk --features native: load, relocate, initialize and execute; fuel-bounded infinite loop; every truncated prefix of an ELF fails cleanly.
  • cargo test -p rd-vm --features native --test native: Dalvik → JNI round-trips on x86_64, arm64-v8a and armeabi-v7a (softfp). Covers add, wide, float, 8 arguments, strings, echo, arrays, mutate, callback, RegisterNatives, throw, snprintf integer formatting, GetStringUTFRegion/GetStringRegion, ExceptionCheck, floating varargs (%.3f %g %.2e) with fmodf/floor, and a missing import (getaddrinfo) reported as NOT_IMPLEMENTED.
  • cargo test -p rd-ndk --features native --lib: %f/%e/%g rendering checked against C printf (18 cases, including round-half-even).
  • cargo test -p rd-vm --test m9: 7 component tests (IME, InputConnection and IME lifecycle, notifications, channels, RemoteViews/widget provider, accessibility, and unknown APIs failing typed).
  • ELF parser mutation campaign (crates/rd-ndk/examples/elf_campaign.rs): over 164M mutated inputs (about 130M of them accepted as structurally valid) ran in 12 minutes with no panic.

Real APKs: bash golden-apks/native-gate.sh (pinned by SHA-256, cached under golden-apks/cache/, output in target/m9-native-gate.json). Every APK must make at least one JNI method call from its real DEX, and the script checks each result. RD_NATIVE_ABI=arm64-v8a or RD_NATIVE_ABI=armeabi-v7a runs the same APKs’ ARM libraries; the output goes to target/m9-native-gate-<abi>.json. The CI native job runs the gate on all three ABIs, with the APKs cached by script hash.

Several fixes and additions came out of this work:

  • JNI table bug. Slots 226–228 were off by two; per the JNI spec, ExceptionCheck is 228. This is now fixed.
  • Instruction accounting bug. The worker reports a running per-call total with every event, and the client used to add each report again. That inflated the counts; for example, an earlier note said the QR call took about 1.09 billion instructions. Only the increments are counted now. The 5M per-call fuel cap was always enforced by the worker itself.
  • ARM fixes.
    • The SVC detector tested Thumb-2 32-bit encodings as ARM-mode SVCs. It now checks the CPSR T bit, which removes false positives.
    • Unused jvalue bytes and r1 are dropped for 32-bit values.
    • Variadic J/D/F arguments now use aligned register pairs, with float promoted to double.
    • getauxval returns the HWCAPs Unicorn emulates.
  • New JNI functions. GetStringRegion, GetStringUTFRegion, Get/ReleasePrimitiveArrayCritical, Get/ReleaseStringCritical and MonitorEnter/Exit.
  • New libc/libm shims. memchr, wmemchr, wcslen, strncmp, strstr, __strchr_chk, posix_memalign, the libm subset and C-exact %f/%e/%g (unit-tested against C printf, including round-half-even).

Limite conhecido: instruções AVX (VEX/EVEX) no worker (issue #400)

O Unicorn 2.1.4 executa código VEX/EVEX de forma errada: floor(5.5)+0.25 virava 0.25 numa biblioteca compilada para x86-64-v3. Por isso o worker rejeita essas codificações com NOT_IMPLEMENTED antes de executar a instrução, em vez de devolver um valor errado em silêncio.

  • Fixtures de referência usam -march=x86-64 (baseline SSE2). golden/native/build.sh também gera x86_64-avx2.so (-march=x86-64-v3) como fixture negativa.
  • Teste: avx_encoded_guest_code_is_rejected_fail_closed_400 (crates/rd-ndk/tests/native.rs).
  • Bibliotecas reais compiladas com AVX não rodam neste worker. Esse é o limite documentado, não um suporte. A correção definitiva depende de um Unicorn com VEX correto ou de outro emulador.
